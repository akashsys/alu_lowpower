You are provided with an incomplete RTL implementation of a 16-bit ALU integrated into a power-aware system. DESIGN ARCHITECTURE AND CLOCKING-
The system is partitioned into a power-gated ALU domain and a top-level controller that manages clock enabling and output isolation.

Clock Gating: Power-off behavior is modeled via the diss_clk signal. When asserted, the internal clock enable signal (alu_en) must go low.

State Preservation: While diss_clk is high, the ALU internal state must not advance. All sequential logic, including the state machine and cycle counters, must freeze.

Safe Modeling: In real hardware, power gating causes outputs to become unknown (X/Z). You must ensure these unsafe values never propagate to the top-level result.

------------

FUNCTIONAL IMPLEMENTATION REQUIREMENTS-
The ALU processes 16-bit operands A and B based on a 4-bit opcode.

Single-Cycle Operations: The following operations must complete immediately when start is sampled in the idle state:

Opcode 4'b0000: Addition (A + B)

Opcode 4'b0001: Subtraction (A - B)

Opcode 4'b0010: Bitwise AND

Opcode 4'b0011: Bitwise OR

Opcode 4'b0100: Bitwise XOR

Opcode 4'b0101: Bitwise NOR

Opcode 4'b0110: Shift-left logical (A shifted by B[3:0])

Opcode 4'b0111: Bitwise XNOR

Multi-Cycle Sequential Operations: These operations require cycle-accurate modeling of hardware latency.

Multiply (Opcode 4'b1000): Must execute over exactly 4 clock cycles. The busy signal must remain high, and the result is latched only on the final cycle.

Divide (Opcode 4'b1001): Must execute over exactly 8 clock cycles. You must handle division by zero safely by producing a result of zero.

OUTPUT CLAMPING AND ISOLATION
To protect downstream logic when the ALU domain is powered off, you must implement a multiplexer-based isolation clamp in the top module.

Clamp Logic: When diss_clk is active, the top-level result must match the clamp_value defined in the hardware.

Signal Integrity: No X or Z values should ever appear on the top-level output.


Observability: The clamp_value must be driven to the clamp_obs port so it can be verified by the testbench.

PRIORITY AND RESET PROTOCOL
Your implementation must strictly follow this logic hierarchy:

Reset (Highest Priority): Forces the ALU to IDLE, clears all internal counters, and drives the output to a safe value.

Power-Off: When diss_clk is high, the output reflects the clamp value regardless of internal ALU activity.

Functional: Normal ALU results are only visible when reset is high and the power domain is on.
